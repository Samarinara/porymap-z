# Battle editor

Open a pokeemerald, pokefirered, or current pokeemerald-expansion project, select a map, and choose **Battle** beside **Dialogue** in the main tab bar.

- **Trainers & Parties** provides searchable records from `src/data/trainers.h` and `src/data/trainer_parties.h`. Choose a file in the selector above the views, select a record, expand its fields, and click a value. Trainer names appear beside their IDs; Pokémon rows summarize species and level. All existing fields are exposed, including trainer name, class, portrait, encounter music, gender flags, battle format, AI flags, items, party size/reference, species, level, IVs, held items, and custom moves. Battle format uses a Single/Double dropdown, and levels/IV quality use bounded number controls. Ordinary trainer names can be edited as plain text; quoting is preserved automatically. Custom values remain C expressions, with field-specific completion from the project's headers. Source field names and expressions are available in tooltips.
- **Edit Party** opens the selected trainer's referenced party, including custom names without an `sParty_` prefix. Cancelling the save prompt keeps the trainer selected. Switching files offers Save/Discard/Cancel for pending changes.
- **Add Pokémon** appends a starter entry to the selected party (up to six members), using its item/move format. Edit its defaults before saving. **Duplicate Trainer**, **Duplicate Party**, and **Duplicate Pokémon** act on the current selection. Selecting a field inside a Pokémon acts on that Pokémon; selecting a trainer's items or party reference acts on the trainer. Trainers and parties need a unique new C symbol; define new trainer IDs through **Trainer IDs (Advanced Source)**. Select a trainer, party, or Pokémon group and choose the matching **Delete** button to remove it after confirmation. Party controls enforce a maximum of six Pokémon and keep at least one member. Unavailable actions are disabled. Update references when deleting or duplicating records.
- **Advanced Source** edits the complete selected data file, including trainer ID constants. Use it to create entirely new declarations, change party structure/types, or edit syntax outside the structured view. Returning to the structured view shows the current source immediately. **Undo** and **Redo** work across structured edits, party operations, and source changes. Saving retains this history; changing files or discarding changes resets it. Choosing Trainer IDs opens Advanced Source automatically.
- **Battle Scripts** follows the current map's resolved script directory, including shared scripts. Its Script view starts selected. Edit `trainerbattle`, wild battle setup, battle flags, text labels, and other event commands directly; the Dialogue view is available for battle introductions and defeat text. This uses the same scene editor and scope controls as the [Dialogue tab](dialogue.md).

**Save Battles**, Ctrl+S, and Save Project write pending battle data and script edits. Switching the main tabs retains edits; the Battle tab and window title indicate unsaved changes. Changing files, maps, layouts, projects, or closing prompts to save, discard, or cancel. Reload rereads the selected file after resolving pending edits.

Structured field edits patch source spans and retain unrelated bytes and comments. Saves use atomic replacement, preserve UTF-8/BOM and LF/CRLF conventions, and refuse to overwrite externally modified files. If Dialogue and Battle Scripts both open the same file, reload the other view after saving; stale edits are refused on save.


## pokeemerald-expansion

Current pokeemerald-expansion uses `src/data/trainers.party` and `src/data/trainers_frlg.party`, rather than stock `trainer_parties.h`. The Battle editor detects `trainers.party` and opens a combined **Expansion Trainers & Parties** workspace. The FRLG source is listed when present. Both trainer settings and team members appear under the same trainer; **Edit Party** selects its first Pokémon without switching files.

Edit trainer names, class, portrait, battle format, AI and item lists, Pokémon headers, levels, abilities, natures, IVs, EVs, and existing moves. The Pokémon header retains Showdown syntax, such as `Nickname (Species) (F) @ Held Item`; the tooltip shows this format. Unspecified levels display the trainerproc default of 100. Optional fields that are absent, move additions, and other structural syntax can be added in **Advanced Source**. Normal team operations retain the one-to-six member limit. Conditional sections and party-pool resizing require Advanced Source.

Add/duplicate/delete operations and field edits patch the `.party` source, retaining unrelated comments and text. Duplicating a trainer asks for a new `TRAINER_` section ID. The expansion build generates its C data from that source; the editor prioritizes `.party` and blocks corresponding generated `.h` files. Do not create a stock `trainer_parties.h` or edit a generated `trainers.h` to work around the old loading error. These rules follow Expansion's [trainer syntax](https://github.com/rh-hideout/pokeemerald-expansion/blob/master/src/data/trainers.party) and [build rules](https://github.com/rh-hideout/pokeemerald-expansion/blob/master/trainer_rules.mk).

For the optional real-source check, set `PORYMAP_Z_EXPANSION_CORPUS` to a temporary copy of either trainer `.party` file and `PORYMAP_Z_TRAINERPROC` to the Expansion trainerproc executable, then run `./tst_battle expansionCorpus`. With trainerproc set, the test uses the system `cpp -traditional-cpp` before processing edited and duplicated data, matching the expansion build pipeline. It validates source conversion, not a complete ROM build or battle simulation. Older expansion releases or heavily customized formats may still need a different adapter.

## Formats and validation

The structured view supports stock C `struct Trainer` arrays with `[TRAINER_...]` entries and `struct TrainerMon...` party arrays, including all four stock item/custom-move combinations. Nested initializer lists expose items and moves individually. Expressions, comments, escaped strings, and custom fields are retained. Macro-generated declarations and conditional initializer layouts require Advanced Source. Structural edits to conditional layouts and explicitly sized arrays are declined to avoid changing their meaning. The data selector starts with the stock pokeemerald/pokefirered paths: `src/data/trainers.h` and `src/data/trainer_parties.h`. If either is missing, it looks for a unique matching C declaration in trainer-related files under `src/data`. Use **Locate File…** to select a relocated C file inside the project; the choice stays active for this project session. When several candidate files exist, select one explicitly. A missing-file error includes the resolved path and recovery instructions. Symlinks and paths outside the project cannot be saved.

Stock trainer party macros (`NO_ITEM_DEFAULT_MOVES`, `NO_ITEM_CUSTOM_MOVES`, `ITEM_DEFAULT_MOVES`, `ITEM_CUSTOM_MOVES`) and direct union references are supported by Edit Party. FireRed's macro-only placeholder teams remain visible as source expressions; their fields are not expanded. The `.party` adapter described above is separate from the stock C adapter. JSON trainer datasets and arbitrary expansion-specific structures are not covered. Do not rename a JSON file or copy generated C into the expected location to bypass a loading error.

Field edits check correctly nested delimiters and reject attempts to insert multiple fields. This is a source editor, not a C compiler or battle simulator. Keep party flags, party union member, array type, size, references, and trainer ID definitions consistent. Strings retain their source quoting and `_()` wrappers. Raw source can contain incomplete code, and adding/deleting records does not automatically update script references or assign trainer IDs. Compile your project and test battles in game after editing. Wild encounter tables remain available in the existing **Wild Pokemon** tab.

Unsupported games and layout-only mode do not expose battle editing. C trainer data remains available in Emerald/FireRed projects using Poryscript, while the Battle Scripts workspace is disabled to avoid editing generated scripts. The separate Dialogue main tab retains its existing Emerald assembly scope.

For an optional test against real source, place stock copies at `emerald/src/data/{trainers.h,trainer_parties.h}` and `firered/src/data/{trainers.h,trainer_parties.h}` below a temporary directory, then run `PORYMAP_Z_BATTLE_CORPUS=/path/to/copies QT_QPA_PLATFORM=offscreen ./tst_battle`. The corpus check parses both formats, checks party macro references, exercises navigation, and verifies a field-edit round trip without saving changes to the copies. This does not compile or emulate either game.
